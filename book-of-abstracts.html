New Csound features, opcodes, and generative techniques

Shaping Musical Texture through Markov-Matrix Operations in Csound

Micael Silva

This paper presents four Csound opcodes for treating a Markov transition matrix as an explicit compositional object: BuildBiasedMatrix generates a matrix from intuitive affinity scores rather than typed probabilities, MatRotate cyclically shifts which state a hierarchy privileges, MatInterp interpolates between two matrices, and MatEntropy relaxes a matrix toward the maximum-entropy uniform matrix. These operations formalize procedures developed by hand across earlier textural compositions, now reusable across symbolic and audio-based work alike, regardless of the specific chain or material involved. Each operation is demonstrated through a short musical example built on a shared nine-state chain, with transition-matrix heatmaps, state timelines, and a Shannon-entropy curve offered as artifacts that consolidate the compositional intent behind each transformation. The result is a small, composition-first toolkit for shaping musical texture, situated within a practice-based approach to computer-assisted musical composition.

ARA and Cabbage, a patch made in heaven?

Rory Walsh

The Audio Random Access (ARA) extension has significantly expanded the capabilities of modern music production by allowing plugins access to entire audio regions. While highly powerful, developing ARA-capable plugins typically requires navigating dense, low-level APIs, a substantial barrier for audio researchers and open-source creators. This paper introduces a new ARA implementation within Cabbage 31. It focuses on the design patterns utilised within the core processing backend to negotiate host-to-plugin asset delivery, thread-safe memory sharing, and time-stamped playback markers within plugin environments. Furthermore, it explores how Cabbage 3 abstracts these low-level ARA callbacks, exposing the raw audio data and region metadata through dedicated Csound opcodes. This gives developers full access to the session timeline and audio assets using standard Csound syntax, enabling custom analysis and processing workflows without requiring complex ARA SDK knowledge.

1 The source code is available at https://github.com/rorywalsh/cabbage3.

Embedding Live Machine Learning in Csound: Emotion-Driven Harmony via an ONNX-Runtime Opcode

Jinlan Zhao, Li (Charlie) Shi, Richard Boulanger

Harmonic generation in Csound typically requires explicit chord specification in the score or coordination with an external process. We present the Affective Harmony Machine (AHM), a system that embeds an Open Neural Network Exchange (ONNX) format machine-learning model as a native Csound opcode, demonstrated through affect-driven chord progression generation. The system trains a Random Forest classifier on 108 annotated jazz and pop chord progressions (six emotion classes, seven scale/mode categories) and exports it to ONNX. We also present emoChord, a Csound opcode that accepts an emotion string, performs live ML inference at i-rate via the ONNX Runtime C API, and schedules emotion-conditioned chord events into a synthesis instrument. No Python interpreter or external process is required at runtime; the current release targets macOS (arm64 natively, x86_64 via Rosetta). The implementation demonstrates a general pattern for embedding ONNX-compatible classifiers as native Csound plugins.

CStore: A Browser-Based Studio for AI-Generated and LLM-Revised Csound Instrument Design

Li (Charlie) Shi, Richard Boulanger

Most text-to-music and text-to-audio systems generate a finished waveform: something to listen to, but not something a composer can directly edit, version, or reproduce. CStore instead generates the underlying Csound project file, and unlike established Csound authoring environments such as CsoundQt and Cabbage, it is built around a generative agent trained on a large, curated corpus of Csound instruments. This paper presents the CStore Web Console, a browser-based studio built on top of that generator that lets a composer draft, audition, vary, and revise Csound instruments without leaving the keyboard. The console pairs a Next.js interface with a Flask sidecar that shells out to the Csound command-line renderer, and organizes work around a library of runs, single-key commands for drafting and playback, and two ways of producing variations: deterministic, score-derived “children” and LLM-driven variants tiered by how far they may drift from a “mother” run. A separate path lets a user hand a rendered instrument to one of six language-model providers with a plain-English instruction, such as “add a plate reverb and lower the pitch by an octave,” and get back a new, separately versioned .csd rather than an overwritten one. We describe the console’s architecture and workflow, and what building a studio around an editable .csd implies for how AI-assisted Csound instruments get made and revised.

Development of fresh interfaces, front ends, and development environments for Csound

Cabbage 3: Not Your Garden Variety Vegetable

Rory Walsh

In an ever-evolving AI landscape, rising subscription costs for proprietary models like Claude and GitHub Copilot threaten to price out small-scale indie developers. To bypass these financial barriers, this paper explores how the Cabbage 3 ecosystem leverages JavaScript to accelerate frontend development. By combining Csound’s high-performance audio processing with decoupled, web-driven frontend architectures, Cabbage 3 provides a highly structured framework for AI-assisted development. Its predictable JSON layout engine, custom-widget boilerplates, and minimalist two-way JavaScript API natively lend themselves to high-accuracy code generation by open-source LLMs without triggering token-heavy hallucinations. Ultimately, this paper argues that Cabbage 3 remains deeply relevant precisely because its structural design bridges the gap between low-friction, AI-assisted web design and human-driven, high-performance DSP.

NERD: A Node Editor for Csound Integration in Scientific and Artistic Contexts

Lovre Bogdanic

NERD (Node Editor for Real-Time DSP) is an open-source, Python-based visual programming environment that organises real-time digital signal processing pipelines as networks of heterogeneous, data-linked nodes on an interactive canvas. Its central feature is a first-class integration with Csound: synthesis instruments authored as standard .csd files are incorporated into any pipeline by adding inline comment annotations that declare their input and output channels; NERD’s meta-parser automatically exposes these channels as typed node ports without requiring any modification to the Csound instrument logic. Surrounding infrastructure—biosignal acquisition, motion tracking, MIDI, OSC, and LabStreamingLayer network streaming—is handled by a library of plugin nodes backed by a daemon-thread worker model. NERD originated in a Volkswagen-Foundation funded research project on musical improvisation and joint action. It has since been used in several scientific and artistic events, including the Science Festival Frankfurt 2024 and the neuroscience outreach event Frankfurt hat Hirn 2026, and a live heart rate sonification installation during an artist-in-residence program in 2025. The software is released under the GNU General Public License (v3) and is available at https://gitlab.gwdg.de/lovre.bogdanic/nerd.

Introducing Dr.C: 40+ Years of Csound and Computer Music, Now an Agentic AI Collaborator for Learning and Building Instruments, Effects, Plugins, and Web Apps

Mateo Larrea, Richard Boulanger

Dr.C is a domain-specialized AI system for Csound. It exists as two independent products built around the same philosophy. Dr.C CLI is a terminal application, a two-column TUI with chat and version history on one side and a live CSD, waveform, and signal-flow view on the other, built for production: scripting, batch rendering, and shipping advanced audio-reactive web applications that open in a browser. Dr.C Standalone is a desktop application built to teach: it ships with a free-tier model out of the box, keeps sound design and code preview inside one embedded window, and adds three things the CLI does not have. A thumbs up/down feedback loop and a store of durable, user-stated “lessons” quietly steer future generations toward a student’s own taste, without ever modeling how skilled that student is. A force-directed Knowledge Graph page renders 34 people, 15 institutions, 25 techniques, and 12 landmark works of computer music history as an explorable, pannable, zoomable map. A Player page turns a finished .csd that exposes its parameters as channels into a MIDI instrument, with MIDI Learn binding a hardware knob to a Csound channel automatically, without manual mapping. Both tools share the same curated retrieval over four decades of Csound community publications, journals, and instrument collections; both propose alternatives rather than finished code; both narrate the history behind a technique as they teach it; and both export working Cabbage plugins. This paper introduces Dr.C as a new kind of collaborator for the Csound community: an AI tutor that draws on the same books, catalogs, and instrument collections its authors have taught from for over forty years, and that is already being integrated into how they teach and how their students explore, design, and compose.

Csound Brain Lab: A Web Environment for Performing and Researching Brain-Computer Music Interfaces

Pedro Sodre, Richard Boulanger, Shiying (Amy) Chen, Wentao (James) Yuan, Xudong (Michael) Zhou, Luoxuan (Angela) Yu, Jiahe (Fancy) Fu and Yuwen (Liora) Meng

The Csound Brain Lab (CBL) is a web-based application that lets anyone get started performing and researching Brain-Computer Music Interfaces (BCMI). It combines the flexible audio-synthesis building blocks of browser-based Csound with one-click connectivity to Muse and OpenBCI headsets through a local bridge, behind a beginner-friendly interface that lets users visualize and listen to their own live brain data, or experiment with a built-in EEG simulator when no sensor is at hand. The system also embeds both remote and on-device large-language models that perform multimodal analysis of EEG and musical material, helping novices find meaningful correlations between brain activity and sound. We describe the mapping layer, in which a chosen target state, a continuously measured affinity to it, and musical parameters expressed as interpolated endpoint pairs together decide what an instrument plays; and we report four preliminary research studies and two EEG composition and performance systems now being prepared with it, each packaged as an application of its own.

Csound in the MetaVerse - Make It Yours: Personalizing Instruments, Worlds, and Live Sound in CsoundMeta

Strong Bear, Richard Boulanger

CsoundMeta is an immersive multiplayer environment, built in Unity for Meta Quest headsets, that lets performers touch, shape, and share Csound instruments as physical objects in a shared virtual or physical space. Since the system’s Orbs, Wanderers, and AI-generated Worlds were first introduced, our central goal has shifted from handing performers a curated palette to play with, toward giving every Csounder the tools to build that palette themselves. This paper documents three developments that carry that goal forward. First, performers can now bring their own Csound work into CsoundMeta from further away than the headset itself: any .csd file becomes an importable sound for an Orb or Wanderer, Cabbage-authored .snaps files import as ready-to-use presets, and a companion web application now lets a performer upload an instrument, complete with its samples, from a desktop browser, with a Dr.C-based assistant on hand to help design, modify, and debug a Csound instrument that will not yet compile. Second, the AI-generated Worlds that once came from a fixed, curated set can now be prompted, remixed, and renamed from inside the headset itself, and repositioned and rotated so a stage arrangement rehearsed at home lines up exactly once the same World is loaded on the performance stage, and every performer, whether standing shoulder to shoulder or joining from across the world, lands in the same generated room and can hand instruments to one another there. Third, and perhaps most consequential for ensemble work, we rebuilt the live audio pipeline around a native engine that carries the microphone-to-effect-to-speaker signal path outside Unity’s own audio thread, fast enough that we now rely on it for real-time capture, playback, and processing shared live across every client in a session rather than kept local to one, and judge it, as musicians do, by ear. Around that engine we added a dedicated, proximity-gated Mic instrument that can also serve the whole session as one shared microphone with automatic handover between performers, an overdub-capable sampler that records from any source in the patch and shares every take across the room instead of keeping it local, and a separate spatialized voice channel with hands-free push-to-talk for talking through a session without breaking it. We also describe the session tools and in-headset tutorials that keep a room full of personalized instruments and new performers from tipping into chaos. Together, these features move CsoundMeta from a system performers play inside toward a system they compose, build, and record in, one shaped as much by the Csound community as by its designers.

Utilizing Csound on embedded systems

Csound on Embedded Risc V and Xtensa Architectures

Aman Jagwani, Victor Lazzarini

With Csound 7, support for bare-metal microcontrollers with ARM Cortex CPUs was introduced. This allowed Csound applications to target these embedded platforms without OS dependencies for the first time, expanding the possibilities in areas such as custom instrument design, interactive art installations, and DIY performance systems. This paper extends this work to two more embedded architectures, RISC-V and Xtensa, through the introduction of Csound for the ESP32 series of microcontrollers. These chips are widely available, very inexpensive, low-power, usually dual-core, and support extensive wireless networking capabilities. They also run FreeRTOS, providing an unexplored middle ground between bare-metal systems without schedulers and complete operating systems. This balance between extensive features and accessibility makes them an ideal target for expanding Csound’s range of supported platforms. In this paper, we describe the process of porting Csound to these platforms, highlight their benefits and limitations in relation to previously supported platforms, and discuss potential use cases and applications of Csound on these platforms.

Innovations in sound synthesis and processing techniques

OnLive 音: A Browser-Based Real-Time Audio Effects System Using Csound

Lihong Tao, Richard Boulanger

Many digital sound tools are powerful, but the technical barrier to entry in DAWs can make them hard to approach. This paper presents OnLive 音, a browser-controlled real-time audio effects console for live input and uploaded samples, built on Csound with a React performance interface. It treats real-time audio processing like a pedalboard rather than a production suite: the user picks an audio source, toggles effects, adjusts controls, and hears the result immediately, without having to build a full digital audio workstation (DAW) session. And every effect can be opened to reveal the Csound .csd file behind it, so users can see exactly how each sound is made and start learning Csound itself. This paper explores how a browser interface can make the depth of Csound directly playable in live performance, through the design and implementation of OnLive 音.

An Analysis-Guided Workflow for Constructing Playable Csound Physical Models: A Tupipa Case Study

Yao Ma, Wanjun Yang

The Tupipa is a traditional three-string plucked lute from southwest China whose sound is preserved mainly through recordings and documentation. Its three strings form two courses: a double course tuned in unison and a single-string course, the latter providing a controlled first case for playable modeling. Such materials document performance practice but do not provide playable controls for physical-model synthesis. This paper presents an analysis-guided workflow for constructing playable Csound physical models from recordings, supplemented by limited physical measurements. The workflow combines ATS and time-domain analysis of recordings with rule-based parameter initialization, diagnostic acoustic-descriptor comparison, bounded local parameter search, and listening-panel calibration. The case study therefore focuses on the single-string course and links measured plucking position, ATS F0, partial balance, decay, and residual/noise cues to Csound controls. In the model-construction stage, initialized controls are instantiated as a four-layer Csound instrument: a wgpluck2 core string-vibration layer, a plectrum-contact layer, a friction/noise layer, and a body-response layer. Rather than introducing another instrument-specific synthesizer, the study shows how recordings can become playable, physically interpretable Csound instruments while retaining listening judgment in the final calibration stage.

Four Routes Through Hyperspace: Wavetable Navigation Strategies via Givens Rotations

Luca Bimbi, Anthony Di Furia, Giuseppe Silvi

This paper presents an approach to navigating the hyperspace of a wavetable, interpreted as a vector in ℝN, based on Givens rotations. A discrete audio signal of N samples is treated as a point in N-dimensional Euclidean space; Givens rotations, acting on pairs of coordinates through the sine and cosine of an angle, displace this point while preserving the L2 norm. Four strategies for selecting rotation pairs and angles are proposed and compared: a local adjacent chain, a non-local prime step, Sobol quasi-random sequences, and a Kuramoto coupled-oscillator model. Each strategy is realized both as an interactive Python prototype and as a Csound plugin opcode operating on 1024-sample wavetables. A preliminary, qualitative audio observation of the four strategies under controlled parameter sweeps is also reported, with a supplementary rendering dataset.

A Vision-to-Music System for Accessible Interactive Sound Experiences Using Computer Vision and Csound

Will Chen, Richard Boulanger

This paper presents a real-time vision-to-music system designed to explore an accessible and interactive auditory experience for people with visual impairments. A webcam feeds a Python/OpenCV application that identifies up to five prominent colored regions as object candidates and extracts each one’s position, relative size, and dominant color. These features travel to Csound over Open Sound Control (OSC), where five continuously running synthesis instruments turn them into an evolving soundscape: horizontal position sets stereo panning; vertical position controls pitch, chord voicing, or rhythmic pattern depending on the voice; relative size shapes amplitude, filter cutoff, reverberation, and delay; and the scene’s dominant color selects one of eight musical modes shared by all five voices, so color becomes harmony. The soundscape continues to evolve through timed chord changes and slow modulation even when the visual scene remains still. The system demonstrates how computer vision and real-time synthesis in Csound can support a musical, nonverbal form of environmental interaction alongside existing assistive approaches.

Binaural Explorer: Theta. A Csound & Cabbage-based System for Real-Time Auditory Entrainment

Yuqi Wu, Richard Boulanger

This paper presents Binaural Explorer: Theta, a cross-platform Cabbage plugin that embeds precise theta-frequency binaural beats directly into existing music, generative soundscapes, and live DAW environments. The plugin uses the Csound synthesis engine to apply a real-time spectral phase vocoder, superimposing a neurologically-active theta differential (4.0–7.2 Hz) onto arbitrary audio signals without degrading the underlying sonic structure. Users can substitute source tracks, activate a fully binauralized generative composition mode, and fine-tune target beat frequencies via granular controls. The system includes dynamic visual feedback (a pulsing “beating cabbage” graphic scaled to the live theta rate), an interactive educational mode, and a linked informational pane for psychoacoustic study. A small early-adopter cohort reported reduced sleep latency, enhanced study focus, and a striking expansion of the perceived soundstage. This readily-customizable, open-source tool functions as both a research utility and a pedagogical toolkit, supporting informal clinical research, interactive sonification, and meditation practice.

A Rapid Opcode Development Workflow for Real-Time Physical Modelling in Csound

Juliette Tudoce, Vasileios Chatziioannou, Alex Hofmann

Implementing a custom physical modelling opcode in Csound requires fluency in C programming, a skill that remains a significant barrier for many musicians and researchers in music acoustics, despite the strong potential of physics-based sound synthesis. This paper presents a development workflow for creating a Csound opcode, illustrated through the case study of the Đàn Bầu, a Vietnamese monochord instrument plucked by the right hand and pitch-bended by the left hand through a stem that modulates the tension of the string. Starting from a generic string model drawn from the acoustics literature, we first prototyped it in Python, allowing for straightforward implementation and assessment of the energy balance. We then translated the Python code into C with the help of Large Language Models (LLMs), which produced a functionally correct translation in a single pass. Finally, the resulting C code was manually adapted into an opcode plugin, enabling its integration into Csound. This case study suggests that the complete process from mathematical model to performable instrument through Csound can be achieved without deep C programming expertise. The workflow presented here offers an illustrative example that musicians and researchers in music acoustics may draw on when developing other physical modelling opcodes for real-time implementation in Csound.

Performer skills in Live-electronics

Spatial Agents: A Timbre-Driven Ambisonic Instrument for Live Electronics in Csound and Max

Alberto Maria Gatti, Francesco Perissi

Spatial Agents is a live-electronics instrument built on a single premise: that the place of a live sound should follow its timbre. Five piezoelectric contact microphones on a hand-built resonating box are analysed in real time into five audio descriptors, and those descriptors move five autonomous sources, or agents, through an Ambisonic field decoded to a horizontal loudspeaker ring or to headphones. The paper is as much about a compositional stance as about a system. Following a tradition of spectral and timbre spatialisation, we treat space not as a container for sound but as a dimension the performer shapes directly: a still, pure resonance settles near the centre of the field, a bright gesture rises, a noisy evolving texture is thrown to the periphery and set spinning. We describe how the descriptors map to motion, focusing on a mapping in which spectral stillness and purity pull a source inward while spectral change pushes it outward, and we explain why we run Csound as the engine inside Max rather than Csound alone: the pairing joins Csound’s analysis and synthesis vocabulary and its portable, sample-accurate processing to the live routing, control and visual feedback that a performance patch needs. The Ambisonic decoder uses the ACN/SN3D convention and is rebuilt at run time from a description of the loudspeaker layout. The approach adapts a descriptor-driven spatialization model previously introduced for corpus-based improvisation; what is new here is a self-contained Csound engine, built from scratch and driven live by a physical contact-microphone instrument rather than a pre-analysed corpus. The instrument is functional and has been validated; we close with the compositional questions it opens and with work still in progress.

One Environment, One Chain: Csound's arduinoRead as a Native Sensor Interface for Performance-Oriented IMU Control

Jinlan Zhao, Richard Boulanger

Live performance leaves little room for a sensor pipeline that misfires. When a violinist’s gesture is intended to trigger one sound but produces two, the error is immediate and audible, and mapping design alone cannot fully compensate for it. This paper presents L-Bow, a wrist-worn six-degree-of-freedom (6-DoF) inertial measurement unit (IMU) controller for augmented violin performance, designed and built by the authors, and asks whether the sensor-to-sound pipeline can be made more reliable by removing an intermediate software layer. L-Bow integrates gesture sensing, six performance modes, and a shared effects chain within a single self-contained Csound file, using Csound’s native arduinoRead opcode for Arduino communication rather than a Python serial parser and OSC bridge. A controlled trigger test comparing the two workflows showed a modest latency advantage for the native path. The paper discusses what this means for designing dependable, low-maintenance performance systems, and where the native approach still falls short.

Algorithmic composition and sound processing techniques with Csound

csonus: An open-source collection of opcodes for algorithmic composition and experimental sound design

Valerio Orlandini

While the Csound ecosystem provides a vast library of tools for synthesis and signal processing, practitioners in real-time algorithmic composition and experimental sound design often encounter a gap in native, instrument-level opcodes for complex generative processes. This limitation frequently forces composers into hybrid workflows with external environments, introducing latency and synchronization overhead. This paper introduces csonus, an open-source collection of C++ opcodes designed to bridge this gap by integrating algorithmic composition and sound generation techniques directly into the Csound instrument block. Built using the Csound Plugin Opcode Framework (CPOF), the package provides efficient implementations of diverse tools, including chaotic systems, cellular automata, Lindenmayer systems, and neural network-driven synthesis. By enabling tightly coupled, multi-level algorithmic decision-making and experimental sound manipulation without external dependencies, csonus fosters a more integrated workflow for both studio and live electronics contexts. The library is written in modern C++ and is publicly available under the MIT license.

From Brainwaves to Csound: An Exploratory Audiovisual System with EEG and LLM-Based Agent Control in Unity

Chuhan Gao, Richard Boulanger, Mateo Larrea Ferro

We present an exploratory audiovisual biofeedback system that integrates real-time electroencephalogram (EEG) signals, large language model (LLM)-based assistance, and Csound within Unity, a real-time game engine, transforming a listener’s brain activity into continuously evolving sound and a synchronized visual scene. NeurOSC, a Python-based EEG acquisition and signal-processing layer, estimates power within five predefined EEG frequency bands, calculates their cross-channel mean relative composition, and sends these features to Unity via Open Sound Control (OSC). Unity converts the features into Z-scores using a calibration reference established for the current session and assigns one of five system-defined state labels: Focused, Relaxed, Aroused, Drowsy, or Neutral. The system uses an LLM in two roles. Before a session, a mapping assistant combines the creator’s natural-language intent with a catalog of Csound parameters parsed from the instrument’s Cabbage header and proposes EEG-to-Csound bindings that the creator can audition and revise. At run time, a scene agent responds to confirmed state transitions and other configured events. It sets larger-scale base targets for selected Csound parameters and issues coordinated visual actions, while a continuous path maps changing EEG features to smaller-scale modulation around those targets. The prototype runs in real time with a Muse S Athena headset and includes a simulator for development without hardware. Its contributions are a human-in-the-loop mapping workflow that combines parameter auto-discovery with LLM-generated suggestions, and a two-path architecture that combines continuous physiological modulation with discrete, context-informed audiovisual changes.

Exploring Csound's educational potential

Orchestrating an Interpreter: Csound7 as a Host for Symbolic Programs

Hlöðver Sigurðsson

This paper evaluates Csound7’s Orchestra language as a host for complex symbolic programs. As a case study, I implemented a Clojure-inspired Lisp interpreter entirely in Orchestra using the Make-A-Lisp process. The interpreter uses recursive structs, arrays, and typed user-defined opcodes to implement lexical environments, closures, macros, tail calls, and exceptions. A musical example uses first-class graph values to build instruments and schedule musical patterns, keeping the symbolic program and audio engine in one process. The work exposed defects in type propagation, nested struct arrays, overload selection, pass-by-reference semantics, recursion safety, and default initialization, leading to fixes merged into Csound7’s development branch. The main limitation in the version studied here was memory lifetime: temporary recursive values persisted until the enclosing instrument ended, making even a small self-hosting test costly in memory. The result shows that Csound7 can support substantial symbolic programs close to its music engine, and that the lifetime of structured values matters for programs that allocate heavily.

Unleashing creativity and fostering interdisciplinary collaborations through Csound projects

A Toolkit for Empirical Impulse Response Preparation

Victor Lazzarini

Empirical impulse responses can be obtained by measuring physical systems. Csound has built-in means for utilising these in musical applications through its various types of convolution opcodes. Until now, the system lacked out-of-the-box means for preparing empirical impulse responses, although this can actually be implemented from first principles in Csound code. This paper introduces a native toolkit developed for this purpose, in three forms: a utility, a GEN, and opcodes.

Immersive Engagement: Building the "Wildtrace" Sonic World with AI Assistance

Haokun Yang, Wanjun YangPresenter: Miao Zhang

This paper addresses the high cost and long development cycles of custom audio plugins by proposing an agile workflow that couples Csound with large language models (LLMs). Building on this workflow, we developed Wildtrace, a quadraphonic spatial audio plugin suite driven by a family of generative algorithms. The core idea of the suite is to invert the usual premise of spatial audio design: rather than moving sound objects through space as an end in itself, it treats the spatial motion of sound as the engine that drives sonic effects such as Doppler shift, panning, granulation, and chorus, so that motion shapes the sound instead of merely positioning it. The paper systematically describes the development logic, the human–AI collaboration model, the layered technical architecture built around a replaceable global renderer, and the self-designed front-end interaction. We assess the approach against conventional C++ plugin development: although no systematic benchmarks were run, the qualitative evidence is encouraging—eight plugins were completed and tested in under one month at zero direct API cost, demonstrating a viable paradigm for agile audio prototyping under resource constraints.

Neural Virtual Analog Modeling in Csound via Real-Time Recurrent Inference

Ken Kobayashi

Csound’s native virtual analog opcodes rely on fixed algorithmic structures that cannot learn transfer functions from empirical data or capture physical analog hardware. We present a real-time neural inference pipeline integrating Csound’s C++ Plugin Opcode Framework (CPOF) with the RTNeural engine, executing stateful recurrent networks directly within Csound orchestra syntax. We evaluate the pipeline on two targets: a parameterized 4-pole Moog ladder filter trained on oversampled numerical simulations, and a fixed-setting analog distortion pedal trained on physical loopback recordings. For the filter, shortening the loss-masked training warmup to 256 samples forces rapid convergence from a cold hidden state, enabling click-free note-on with only a brief output ramp; reducing the warmup further to 128 samples reduces static ESR at the 100 Hz cutoff by 7.6 dB. A multi-rate LFO training regime addresses dynamic tracking degradation: a static-trained 128-unit baseline degrades by 17.3 dB under a 5 Hz cutoff sweep, while multi-rate LFO training compresses rate-dependent variance to 3.6 dB across 1–20 Hz on held-out audio. The same recurrent architecture, without the cutoff input, achieves −29.3 dB held-out ESR and −37.9 dB aliasing-to-signal ratio at 8 kHz on the hardware distortion pedal when trained via pre-emphasized ESR on loopback recordings. Deployed 128-unit Gated Recurrent Unit (GRU) opcodes consume under 17% CPU per voice, sustaining 6-voice polyphony at 48 kHz.

Real-time implementation of Csound

Real-Time Song Generation: A Csound API Case Study

Garrett Eckl, Steven Yi, Edward Costello, Leonardus Van Der Ploeg

This case study presents RIFFIT, a commercial text-to-song platform that utilizes the Csound audio programming language. This platform enables users to turn any text into a fully-produced song in near real-time, with a variety of genres and voice models to select from. Csound serves as the platform’s primary synthesis engine, performing a custom CSD file that is dynamically generated based on both the inputted text and selected musical preferences.

This paper begins with a brief introduction to the field of automatic music generation, which is followed by an overview of the RIFFIT platform and key developments that have occurred to date. The software’s architecture is then outlined, with topics including the dynamic generation of Csound code, the manual performance of Csound files via the Csound API, and strategies for the web deployment of Csound-enabled software. Lastly, an analysis of Csound’s suitability for such commercial applications is provided.

Contributions engaging with the work and legacy of Gottfried Michael Koenig and James Tenney

The Process of Constructing Postcard from Sertões within a Csound Environment

Catarina Rossi, Bruno Gazoni

This paper describes the creative and technical process of the performance Postcard from Sertões. The work details the transposition of Almeida Prado’s Sertões (1978) for solo viola [1] into the interactive electroacoustic domain, inspired by the compositional economy of James Tenney’s Postal Pieces (1971) [2]. The research was developed within an Interpretive Experimentation Laboratory, which consisted of distilling Prado’s “transtonal system” into four essential sound blocks, interpreted as “clangs”, primary perceptual units based on Tenney’s theory. The performance establishes a bridge between written tradition and orality by distributing musical materials between two distinct performers. An acoustic interpreter plays the Brazilian rabeca and the viola, while an algorithm interpreter manipulates the audio input in real-time. The implementation, done via Csound and Cabbage, involves a digital signal processing (DSP) system operated by a postcard-inspired visual interface. Through four looper tracks enhanced by effects, the algorithm interpreter reshapes the clangs’ identities. The laboratory explored and refined the interaction protocol between the musicians through remote testing and in-person rehearsals. Francesco Vitucci

Fixed · 5'00"

Lumina is an autonomous five-minute stereo fixed-media composition developed from materials created for IHM, a larger work for four cellos and live electronics based on three historical operatic representations of Dido by Henry Purcell, Domenico Sarro, and Niccolò Piccinni. The composition investigates the persistence of vocal identity after fragmentation. A corpus of recorded vocal material is segmented into syllabic units through a Praat-assisted procedure. Each fragment is analysed using MFCC data and eight spectral descriptors: centroid, crest, flatness, kurtosis, roll-off, skewness, slope, and spread. The resulting feature vectors define a multidimensional timbral space in which constrained stochastic paths generate sequences according to spectral proximity rather than textual syntax or melodic continuity. These sequences are articulated through a hierarchical temporal structure derived from interacting periodic cycles and rendered in Csound as dense streams of overlapping, windowed sampling events. The resulting form moves continuously between partially recognisable vocal traces and more fused, quasi-instrumental textures. The stereo field contributes to this process by differentiating simultaneous layers, shaping transitions, and controlling the perceived convergence or separation of the materials.

Csound EEG Duet #2

Shiying (Amy) ChenRichard Boulanger

Live Electronics · 8'00"

Csound EEG Duet #2 is a live electroacoustic work for two performers, each wearing a Muse Athena EEG headband and streaming Delta, Theta, Alpha, Beta, and Gamma band data via OSC into Csound from four sensors (TP9, AF7, AF8, TP10). The four streams per band most often generate four independent voices or four-part harmonies; in solo passages, they instead shape the detuning, mix, and filtering of a single four-oscillator instrument. MIDI keyboards and faders let each performer trigger, gate, and transpose the sound, so the EEG data becomes audible only when a key is pressed, at a rate the player sets. Across eight differently mapped Csound orchestras, the piece moves between unquantized harmonies drawn directly from the fluctuating brainwave data and more focused, quantized, reharmonizing textures. Each performer runs The Csound Brain Lab, which hosts the EEG connection and projects EEG-responsive, audio-reactive visuals synchronized to the selected orchestra. Over 8 minutes, the performance moves from raw, exotic harmonic material toward focused chordal writing and a brief melodic solo, then dissolves back into the unpredictability of the original data streams.

Symbol X: Six Unbalanced Equations for Violin and Live Electronics

Jinlan Zhao, Composer & Performer (violin and L-Bow)

Mixed · 8'00"

What does it mean to live inside an equation that has no solution? Symbol X: Six Unbalanced Equations for Solo Violin and Live Electronics is a work for live violin and live-processed electronics in six scenes, each built around a mathematical symbol that portrays the problems and dilemmas women face in different social contexts. The electronics are driven entirely by a wrist-worn IMU controller that the composer built and wears during performance, routing gesture data into Csound in real time; there is no fixed medium and every sound is generated live. Beginning with the undefined equation of 1/0 and ending in the self-evident simplicity of 1+1=2, the piece traces a path from the unease of being watched toward a temporary space of equality.

Butterfly Effect

Cesare Saldicco

Fixed · 10'00"

Written on the occasion of the centenary of the death of Giacomo Puccini, Butterfly Effect is a composition that revolves around quotations of themes drawn from Puccini’s opera, reworked, assembled, and shaped by a simple question: what would have happened if Madama Butterfly had not taken her own life? This hypothesis leads us to reflect on the potential ramifications and the different directions that the story of the young Japanese geisha might have taken if its main events had been altered. By imagining an alternative ending in which Butterfly chooses to face reality and pursue a new path in life, the work confronts us with questions such as: how would her relationship with Pinkerton have developed? How would it have influenced her relationship with her son? And what impact would it have had on her experience of migration and adaptation to a foreign culture? Without the tragic choice of suicide, the plot of Madama Butterfly could have taken an unexpected turn, opening up new scenarios and conflicts. These hypotheses—explored through the theory of the so-called butterfly effect—invite us to consider the infinite possibilities of an alternative narrative, while at the same time preserving the dramatic power and deep reflection offered by Madame Butterfly’s tragic decision.

Echoes of the Unseens

Jacopo Greco d'Alceo

Live Electronics · 10'00"

Echoes of the Unseens is an electroacoustic co-composition realized through a hybrid duo performance system that combines live coding with analog electronics.

The piece gives rise to sonic entities through real-time gesture, translating an industrial nightscape—a threshold between earth and concrete—into a shifting sound-image. Its dramaturgy draws on Pierre Henry’s Entités, featuring two protagonists engaged not in strict counterpoint but in a dialogue closer to sonic gesture. The urban environment and its nocturnal mystery are informed by Charles Ives’s Central Park in the Dark, while the visual imagination of Edward Hopper shapes the treatment of solitude and stillness within a vast, largely static soundscape.

Positioned between solitary performance and the evocation of a plastic tableau, the piece stands as a hymn to minority, to the unseen, to those kept hidden.

Transmutational Interplay for Piano and Csound

Yuwen (Liora) Meng, Piano

Mixed · 8'00"

Transmutational Interplay for Piano and CsoundLive is a solo piano piece reshaped live by a second performer processing the piano signal in real time on CsoundLive, a browser-based Csound 7 performance environment built around 22 time-based and 12 spectral effects, Muse2 EEG and MIDI-mapped controls, and an internal live-input, sampler, and player mixing architecture. No sampled or pre-recorded material is used at any point; every sound in performance is the piano, reshaped as it is played. The accompanist draws on seven of CsoundLive’s time-based effects: a flanger, a rhythmic gate, a resonator, a pitch harmonizer, a shimmer reverb, a real-time granular processor, and a slow spectral “accordionizer” that stretches and compresses the piano’s harmonic content the way a bellows moves air, bringing each in and out across a single emotional arc: an unsettled, searching opening; a harder passage of real hesitation; the gradual arrival of warmth and reassurance; and a more open, hopeful close, voiced as though the performer’s present self were speaking back to an earlier, less certain one. The two performers work like a jazz duo: the pianist states the piece’s motives, and the accompanist answers, stretches, and leans into them live, so the balance of the seven effects shifts from one performance to the next even as the piano’s material stays fixed.

P l e n u m (Groot Auditorium Leiden)

Michele Del Prete

Fixed Media · 10'13"

P l e n u m is a series of pieces devoted to the exploration of site- and instrument-specific constellations through electronics realized exclusively in Csound. The series investigates the phantasm of the organ’s full presence—a sonic effect traditionally achieved, in its ideal form, through the plenum: the organ registration in which several, potentially all, aliquot stops are added to the principal.

For P l e n u m (Groot Auditorium Leiden) I recorded several sound combinations of the 1998 Flentrop organ at Groot Auditorium, an instrument built after 17th-century Dutch models. The compositional process involves creating a plurality of microtonally shifted textures in which the recorded material is transposed by gradually increasing factors and enriched through multiple artificial plenum gradations. The aliquot strata are algorithmically generated to replicate the mixture structure of the Flentrop organ. At the formal level, echo sections play a key role, as they do in several Fantasias by Jan Pieterszoon Sweelinck.

In the co-presence of multiple organs within the same space, the question of the polyphony of space becomes immediately striking. Yet even within the spatiality of a single organ, the multiplicity of sound sources remains a crucial issue. Polyphony is a fundamental category of organ music; organ placement is an extremely complex subject, and the question of sound projection in the electronic realm is itself immense. A kind of mise en abyme therefore emerges in the relationship between organs, electronics, and spaces. I conceive my P l e n u m series as a contribution to this exploration.

In memoria di Giuseppe Ganduscio

Giovanni Damiani

Fixed Media

The piece In memoria di Giuseppe Ganduscio is a tribute to a relevant but little-known Sicilian ethnomusicologist, poet, and political figure. Ganduscio (1925–1963) is known to me through a recording of an interview that Luciano Berio made in 1962, together with Cathy Berberian, Roberto Leydi, and others. On that occasion, Ganduscio sang and explained his personal criteria for preserving and transmitting Sicilian oral-tradition music. There are cases of literal preservation and transmission, but there is also, for example, a blessing song that he transformed into a political challenge, with the words “amo a canciari ’sta sorti mischina” (“we have to change this miserable fate”).

Here I sample his late song and this spoken text—his tenor voice alone being already evocative—and I transform the text myself, separating the text from its melodic contour and also applying the spoken text to the melodic contour of the song. Through LPC (Linear Predictive Coding), I use time-stretching, freezing, and the extraction of only the noisy or vocal component, as well as formant shifting. This can change, in a striking way, the perceived age of the virtual singer, from a child to an aged and decrepit voice. After a monophonic freeze on the upbeat of the melody, the spectral components are scattered through space in a powerful dynamic and spatial explosion.

The piece is dedicated to Luigi Pestalozza, a great figure in connecting the manifold social levels of music and music research.

Flourishing Blossoms Like a Dream

An Audiovisual Electroacoustic Composition

Hechen WengHaokun Yang

Fixed Media · 7'30"

This proposal presents “Flourishing Blossoms Like a Dream”, a fixed-media audiovisual electroacoustic composition scored for 4-channel quadraphonic audio and synchronized digital video. The work explores the aesthetic dichotomy between ephemeral worldly prosperity and the enduring tranquility of memory through a tightly coupled hierarchical mapping between sound and image. Technically, the electronic audio layer blends pointillistic digital synthesis with granularly processed acoustic wind chime samples. Spatialization is driven entirely by a custom-developed suite of eight algorithmic quadraphonic panning plugins implemented natively within Csound. These algorithms—ranging from orbital trajectories to flocking systems—dynamically distribute the sonic textures across a four-channel speaker array to create a deeply immersive acoustic landscape that cross-modulates with the unfolding visual narratives.

Extrapolation de la campagne

Jean-Basile Sosa

Fixed Media · 20'00"

Extrapolation de la campagne is a research and electroacoustic music project in which the concepts of space and nature lie at the heart of the musical thinking.

In this project, musical space is treated as a fundamental parameter, alongside pitch, timbre, intensity, and duration. From conception to realization, Extrapolation de la campagne was initially produced using a three-dimensional sound spatialization system based on ambisonic technology (3rd order HOA) and a network of twenty-four loudspeakers. To ensure the work’s longevity and wider artistic dissemination, a stereophonic version was subsequently produced.

From a poetic perspective, the project is motivated by an imaginative, artistic and musical exploration of acoustic spaces in natural environments. Indeed, one of the main aesthetic challenges of this new project is to imagine, from the recording of natural soundscapes, new musical spaces that seem close to nature, but that sound synthesis metamorphoses into another field of unheard perceptions. In this sense, Extrapolation de la campagne can ultimately be considered a hybrid and surrealist composition in which electronic sounds musically blend with field recordings made in rural area.

Skeiðarársandur

Jan Jacob Hofmann

Fixed Media

Hardly anywhere are the processes of formation and dissolution of a landscape as clearly visible as in Iceland. Heat and matter there shape the landscape, just as frost, water, and wind decompose it and transform it into something new. The laws of gravity and inertia of mass, in turn, have an ordering effect on what has previously been dismantled. Disintegration and the breaking up of rigid structures are not something negative here, but rather a completely natural part of a permanent, everyday process of transformation. The electronic sounds, spatialized using the Ambisonic method, evoke landscapes of the soul that have their physical, real counterparts high in the north.

Undercurrents

Antonio Scarcia

Fixed Media · 6'32"

This fixed-media work is based on a compositional framework that foregrounds the interaction between sound materials and musical gestures. Materials are conceived as sound entities carrying latent structural relationships, which may remain compositional implicit while becoming perceptually manifest through their audible effects. Gestures function as temporal processes that articulate these relationships and shape the listener’s perception. The work integrates concrete and synthetic, tonic and non-pitched sound materials, organized through strategies of contrast and balance. Gestural processes are formalized as parametric sequences generated via a computer algebra system, with sound synthesis realized in Csound. Although produced using digital technologies, the compositional approach aligns with the tape studio tradition, emphasizing detailed post-processing in both the time and frequency domains as an integral part of the compositional process. “Undercurrents” was composed and premiered in 2026 at ICMC, Hamburg.

When an Android Becomes Obsolete

Giancarlo Alfonso

Fixed Media

This composition investigates the notion of technological and computational obsolescence as a lens through which to reflect on human obsolescence, particularly in relation to mechanical, artistic, and intellectual labor. Within a social and economic climate increasingly oriented toward efficiency and automation, human beings are placed in constant competition with artificial systems designed to be faster, tireless, and free from the limitations that characterize human labor. The piece employs the figure of an android reaching the end of its operational life cycle as a central metaphor for this condition. Its final moments of activity are evoked through states resembling confusion, anger, resentment, despair, and acceptance, not as genuine emotions, which a machine is incapable of experiencing, but as the outcome of internal calculations and self-assessments of its own operational status. This process paradoxically humanizes the android, placing it on the same existential plane as the human beings it was designed to replace, and turning it into a metaphor for the condition of contemporary individuals increasingly rendered superfluous within industrial and productive contexts. Compositionally, the work is built primarily through granular synthesis, complemented to a lesser extent by additive and subtractive techniques. Concrete industrial and metallic sound sources are granulated and processed into disjointed, rigid rhythmic structures that evoke a mechanical system in decline, while colder, more abstract synthetic textures suggest a form of artificial consciousness. The piece unfolds as a continuous friction between mechanical rigidity and timbral instability, tracing the progressive deterioration of the android’s physical and cognitive functions.

Porphyry v7.4.2

Michael Gogins

Fixed Media

This fixed-media electroacoustic work is rendered in Csound using an orchestra that generates pipe-organ audio with Modartt’s Organteq plugin and processes it with the Mverb2020 reverberation plugin. Organteq is a physical model of a pipe organ and does not use samples. The entire score is generated and rendered by a single Python script. Bars of music from the musical dice game traditionally attributed to Mozart are played in sequence, but each bar is repeated a randomly chosen number of times, as in Terry Riley’s In C. Every few bars, the music progresses to a randomly selected chord. Periodically, the current chord is used as a pivot for modulation to a new diatonic scale, and the generated notes are quantized to that scale. The Organteq registration is also changed periodically.
